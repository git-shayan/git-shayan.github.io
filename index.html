Two parts are left: remote access and the SIEM. This is how I plan to do each one, and how I will know it works.

Remote access

  1. Choose one admin path. Administration happens from one defined source, not from any machine.
  2. Harden SSH on the Linux machines. Key-based login, passwords and root login switched off, and only named users allowed.
  3. Restrict WinRM on the Windows machines. Only the admin source can reach it, with separate admin accounts and least privilege.
  4. Enforce it at the router. A firewall rule on the company router allows remote administration only from that source, and the would-drop log shows the rest.
  5. Log every session. SSH authentication logs and Windows logon events are kept, ready for the SIEM.
  6. Test it from Kali. Password guessing and logins from other hosts must fail, and each attempt must show up in the logs.

Done when: remote login works only from the admin path, and every attempt is logged.

SIEM

  1. Collect. Windows Security logs from the domain controller and clients, Linux authentication logs, nginx logs, and the firewall would-drop logs from the routers.
  2. Normalise. Map each source to the same fields: host, user, source address and event.
  3. Build the detections from the detection plan, starting with password spraying, Kerberoasting, SSH and web login brute force, and traffic crossing from IT to OT.
  4. Attack it from Kali. Run each attack against the company site and check that the matching alert fires.
  5. Tune. Remove false alarms using normal activity, so the alerts stay useful.
  6. Write one incident report. Timeline, detection, containment and lessons, for one of the attacks.

Done when: each detection fires on its attack from Kali and stays quiet during normal use.

What the findings show

  • Missing authentication. Four of the six critical findings were unauthenticated access: OS command injection, iSCSI, Elasticsearch and an admin interface.
  • Exposed services. Public NFS shares, a DNS zone transfer, anonymous FTP and SMB enumeration, and exposed administrative and backup services.
  • Weak configuration. SMBv1 and unsigned SMB, a management platform served over HTTP, SSH password logins and an expired certificate.
  • Information disclosure. Sensitive data through Elasticsearch, application details, robots.txt and technology fingerprints.

Tools: Nmap, Metasploit, Burp Suite, Nessus, OpenVAS, Wireshark
